# Bench 2026-08-06 — write loop & batch against lan-host

First live measurement of the write loop, test gate, and batch scheduling
(branch `feat/write-tools-and-batch`), against LM Studio on `lan-host`
(192.0.2.10, Apple Silicon). Two tasks over a planted fixture repo:

- **routes** (read-only, `digest` profile): "List every route in
  `src/routes.ts` that validates its request body, with exact line numbers."
  Ground truth by grep: lines 9, 10, 12 of 6 routes.
- **fix** (write, `fix` profile): "greet() returns 'Helo' — fix the typo."
  Ground truth: one-line edit in a detached worktree;
  `test_cmd: grep -q 'Hello' src/greet.ts` gates it.

**Headline: every model completed both loops.** 6/6 perfect recall with
exact line citations and zero fabrications on the read task; 6/6 (with one
transient retry) held the write loop — read → exact-match `edit_file` →
prose stop — with the gate passing in the worktree and the caller's tree
untouched every time. The design doc's open question 1 ("does a small model
hold a write loop?") is answered for the 1-file case: even 4.6B does.

Batch verified live in the same session: 3 jobs over 2 models grouped
correctly (queue_wait 6–7s = sequential group loading, as designed), the
progress file tracked to a final complete state, and a job pointed at a
dead provider errored in 0s, escalated to `--escalate-tier cheap`, and
recovered — both attempts in the rollup, escalated transcript on disk.

## What the live run caught that 229 tests did not

1. **`tool_calls` echoed without `type: "function"` → HTTP 400** (fixed,
   `cba2666`). `normalizeToolCall` rebuilt wire calls as `{id, function}`;
   LM Studio validates the echoed assistant message and rejects the missing
   `type`. Turn 1 succeeded, turn 2 died. Every scripted test fake accepted
   the malformed echo — the same lesson as the branch's earlier
   fake-embodies-the-assumption findings, now with a live-server regression
   test scripting a `type`-less wire response.
2. **Bun's `fetch` does not resolve bare LAN hostnames that `curl` does.**
   `http://lan-host:1234` failed ("Unable to connect") while curl resolved it
   via the search domain. Use an IP or FQDN in `base_url`.
3. **LM Studio silently serves unknown model ids with whatever is loaded.**
   A tier pointing at `definitely-not-a-model` returned clean answers from
   the resident model. A typo'd model name benchmarks the wrong model with
   no error anywhere. The planned LM Studio adapter's pre-run capability
   probe (`/api/v0/models`) is the fix; until then, check the id list
   before trusting a measurement.

## Operating notes

- Envelope economy held: 1,361–3,907 delegate tokens per task returned as
  400–700-char envelopes; the batch rollup for 3 jobs + 1 escalation was
  ~2.5KB.
- The dense 27B (qwen3.6-27b) is the wrong shape for this host: 4–6× the
  wall of the MoE models at no accuracy gain on these tasks. gpt-oss-20b
  (MXFP4 MoE) was the best big-model value: fastest non-gemma, lowest
  token burn.
- Fixture and scripts: session scratchpad `bench/` (fixture repo,
  `bench.sh`, `results.jsonl`); not committed.
